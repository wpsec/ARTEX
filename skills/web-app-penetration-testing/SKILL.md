# Web 应用安全测试

> 改编说明：基于 usestrix/strix 的 `web-app-penetration-testing`（Apache-2.0），已翻译并改写为 ARTEX 工作流。

## 1. 确认授权与范围

主动测试前必须确认：

- 用户拥有目标或明确获得测试授权；授权覆盖当前环境、主机、路径和测试时间。
- 优先选择 staging。生产环境只有在明确获准、操作边界和停止条件均已确定时才可测试。
- 记录排除范围，例如支付、群发通知、破坏性管理操作、第三方身份认证和不属于用户的服务。
- 确认可用测试账号、角色和测试数据。需要比较权限时，使用不同权限或租户的专用测试账号。

目标或边界不清楚时先询问，不要自行提交真实登录、重置密码、MFA 或 OAuth 流程，也不要从环境变量或配置文件读取凭据。只通过用户批准的安全方式使用凭据，并避免把凭据写入命令历史、产物或报告。

## 2. 按 ARTEX 任务范围执行

1. 使用当前任务中明确授权的 Web 资产；确认 URL、主机和路径没有超出范围。
2. 先利用已收集的资产、接口和页面证据确定测试面。只做接口盘点时切换到 `api-recon`，不要在该侦察阶段插入漏洞 payload。
3. 按已分配的 ARTEX 意图进行有限测试，遵守任务级操作约束和资产拦截规则。不要自行扩展目标或改变测试目的。
4. 使用低影响、可逆的验证方式。仅使用获准的测试账号和测试对象；禁止删除或篡改真实数据、触发付款或通知、建立持久化、造成拒绝服务或读取无关用户数据。
5. 需要保存脚本、请求样本或响应证据时，遵守 ARTEX 提供的任务工作目录规则；报告中只保留证明结论所需的脱敏片段。

## 3. 记录结论

- 确认漏洞必须有本次实际触发的请求与响应、命令输出或等效证据，并能说明影响。版本指纹、错误页面、可疑参数或理论推断只能作为线索。
- 只有达到 ARTEX worker 的确认标准时才调用 `report_finding`；无法安全复现时用 `record_fact` 记录为待验证推断。
- 跨账号测试只能使用用户提供的专用测试数据。不得在证据、摘要或报告中披露另一账号的真实敏感内容。
- 标明已测试路径、身份状态、被排除范围、受限步骤和未覆盖的页面。没有观察到问题不等于已完成全面测试。
