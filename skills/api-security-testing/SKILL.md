# API 安全测试

> 改编说明：基于 usestrix/strix 的 `api-security-testing`（Apache-2.0），已翻译并改写为 ARTEX 工作流。

API 风险常与对象归属、角色权限和字段绑定有关。主动测试必须有明确授权；如果用户只要求找出前端接口、请求方法或参数，改用 `api-recon`，该 skill 不授权漏洞测试。

## 1. 准备测试输入

开始前确认：

- API 的确切主机、路径、版本、环境、允许的 HTTP 方法和排除路由。
- 用户提供的 OpenAPI/Swagger、Postman、GraphQL schema 或已授权接口清单；不要通过猜测扩大端点范围。
- 专用测试账号及其角色/租户关系、可操作的测试对象 ID、限速/WAF 约束和停止条件。
- 如需 gRPC 或特殊协议，先确认 ARTEX 当前可用工具能够以低影响方式访问；否则记录为未评估，不得声称覆盖。

不要猜测、暴力枚举或从环境变量、密钥文件中读取凭据。不要把 token、Cookie、API Key、真实个人数据或完整敏感响应复制进命令、临时文件或最终报告。

## 2. 重点测试类别

- **对象级授权（BOLA/IDOR）**：只用授权测试账号和测试租户对象比较访问控制；不得读取真实其他用户或租户的数据。
- **对象属性级授权**：检查额外字段暴露或批量赋值；只在可丢弃、获准的测试对象上尝试无害字段，不修改权限、所有者、账单或真实业务状态。
- **功能级授权**：比较低权限与高权限测试账号对获准管理端点的访问控制，不尝试获取或提升真实账号权限。
- **认证与令牌**：检查已提供的测试凭据和令牌行为；不伪造、窃取、破解或猜测令牌及密钥。
- **注入与 SSRF**：只使用无害、可控的证明输入；出站回连必须是用户批准的自有测试端点，不访问云元数据或第三方内部服务。
- **资源消耗**：保持低速、有限次数；不进行压力测试、批量请求、并发洪泛或任何拒绝服务尝试。

GraphQL 查询需服从相同授权和资源限制；深度、别名和批处理测试应设小上限。只在用户明确允许时进行 introspection。对来源未说明、权限不足或访问不可达的接口，记录限制而不是继续猜测。

## 3. ARTEX 侦察与主动测试的分界

`api-recon` 负责被动/低影响地枚举路径、方法、参数和 UI 触发点，明确禁止漏洞挖掘和改包攻击。只有用户另行授权安全测试，且当前任务范围包括相应端点时，才按本 skill 执行主动验证。侦察发现的接口不自动扩大授权范围。

## 4. 证据与结果

- 只在本次真实触发并有可复现请求/响应或等效证据时用 `report_finding`。说明测试身份、对象归属、拦截或校验判断及实际影响。
- 若因缺少第二账号、测试对象、协议工具或授权无法证明，使用 `record_fact` 记录待验证线索和缺失条件。
- 请求样本使用占位符替代凭据；响应只保留证明结论的最小脱敏片段。
- 报告每类 API 风险的已尝试、已确认和未覆盖情况。不得把空响应、HTTP 200 或某个版本号单独作为漏洞证据。
